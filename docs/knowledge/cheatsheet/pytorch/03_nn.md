# **PyTorch NN Modules Cheatsheet Generation**

## **Problem**

Create Fully Connected Layer (nn.Linear)

## **Trigger**

Apply an affine linear transformation (*y*\=*xWT*\+*b*) to project feature dimensions in dense networks or classification heads.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, in_features)`  
`x = torch.randn(32, 128)`

`# Linear layer mapping 128 features to 64 features`  
`layer = nn.Linear(in_features=128, out_features=64, bias=True)`  
`output = layer(x)`

`print(output.shape)  # torch.Size([32, 64])`

## **Minimal Notes**

nn.Linear operates on the last dimension of the input tensor, preserving all preceding batch/sequence dimensions. Weights are initialized using Kaiming Uniform by default.

## **Common Bug**

**Issue:** RuntimeError: mat1 and mat2 shapes cannot be multiplied

**Cause:** The input tensor's last dimension does not match in\_features.

**Quick Fix:** Ensure the input feature dimension matches in\_features or reshape using x.view(batch\_size, \-1).

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.Linear.html](https://pytorch.org/docs/stable/generated/torch.nn.Linear.html)

## **Problem**

Create Lazy Linear Layer (nn.LazyLinear)

## **Trigger**

Defer defining in\_features until the first forward pass to automatically infer input dimensions from incoming tensors.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape with arbitrary last dimension`  
`x = torch.randn(16, 256)`

`# In_features is uninitialized until first call`  
`layer = nn.LazyLinear(out_features=32)`  
`output = layer(x)`

`print(output.shape)  # torch.Size([16, 32])`  
`print(layer.in_features)  # 256`

## **Minimal Notes**

Parameters are initialized dynamically on the first forward call, requiring a dummy dry-run before initializing optimizers. Avoid using nn.LazyLinear when loading pretrained model state dicts directly.

## **Common Bug**

**Issue:** ValueError: Optimizer got an empty parameter list

**Cause:** Passing the model parameters to an optimizer before executing at least one forward pass to initialize lazy modules.

**Quick Fix:** Pass a dummy input tensor through the network before instantiating torch.optim.Optimizer.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.LazyLinear.html](https://pytorch.org/docs/stable/generated/torch.nn.LazyLinear.html)

## **Problem**

Create 1D Convolution Layer (nn.Conv1d)

## **Trigger**

Extract local 1D temporal or sequential features along a temporal axis for time-series, audio, or text representations.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, in_channels, sequence_length)`  
`x = torch.randn(8, 16, 100)`

`# 1D Convolution over sequence`  
`conv1d = nn.Conv1d(`  
    `in_channels=16, out_channels=32, kernel_size=3, stride=1, padding=1`  
`)`  
`output = conv1d(x)`

`print(output.shape)  # torch.Size([8, 32, 100])`

## **Minimal Notes**

Expects input in channel-first format (N, C, L). Output length is calculated as *Lout*​\=⌊stride*Lin*​\+2×padding−kernel\_size​\+1⌋.

## **Common Bug**

**Issue:** RuntimeError: Expected 3-dimensional input for 3-dimensional weight...

**Cause:** Passing 2D input (batch\_size, sequence\_length) missing the channel dimension.

**Quick Fix:** Unsqueeze or transpose the input tensor to ensure the channel dimension is at index 1 (N, C, L).

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.Conv1d.html](https://pytorch.org/docs/stable/generated/torch.nn.Conv1d.html)

## **Problem**

Create 2D Convolution Layer (nn.Conv2d)

## **Trigger**

Extract spatial features from 2D structured grids like images, feature maps, or spectrograms.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, in_channels, height, width)`  
`x = torch.randn(4, 3, 64, 64)`

`# 2D Convolution with padding to preserve spatial dimensions`  
`conv2d = nn.Conv2d(`  
    `in_channels=3, out_channels=64, kernel_size=3, stride=1, padding=1`  
`)`  
`output = conv2d(x)`

`print(output.shape)  # torch.Size([4, 64, 64, 64])`

## **Minimal Notes**

Input must follow NCHW layout (batch\_size, channels, height, width). Setting padding="same" preserves spatial dimensions when stride=1.

## **Common Bug**

**Issue:** Unexpected reduction in spatial resolution (height/width) in deeper networks.

**Cause:** Forgetting to set padding when using kernel\_size \> 1 with stride=1.

**Quick Fix:** Pass padding=kernel\_size // 2 or padding="same" to maintain equal input/output spatial dimensions.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.Conv2d.html](https://pytorch.org/docs/stable/generated/torch.nn.Conv2d.html)

## **Problem**

Create 3D Convolution Layer (nn.Conv3d)

## **Trigger**

Extract spatio-temporal or volumetric features from 3D inputs such as video frames, CT scans, or medical volumes.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, in_channels, depth/frames, height, width)`  
`x = torch.randn(2, 3, 16, 112, 112)`

`# 3D Convolution over video or volume`  
`conv3d = nn.Conv3d(`  
    `in_channels=3,`  
    `out_channels=32,`  
    `kernel_size=(3, 3, 3),`  
    `stride=1,`  
    `padding=(1, 1, 1),`  
`)`  
`output = conv3d(x)`

`print(output.shape)  # torch.Size([2, 32, 16, 112, 112])`

## **Minimal Notes**

Input format requires 5D tensors (N, C, D, H, W). Memory usage scales rapidly with depth and spatial resolutions; consider channel-first memory layout optimizations.

## **Common Bug**

**Issue:** RuntimeError: CUDA out of memory during training.

**Cause:** 3D convolutions significantly increase activation memory due to the additional depth dimension.

**Quick Fix:** Reduce batch size, lower temporal/spatial resolution, or use mixed precision (torch.amp).

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.Conv3d.html](https://pytorch.org/docs/stable/generated/torch.nn.Conv3d.html)

## **Problem**

Create Transposed Convolution Layer (nn.ConvTranspose2d / nn.ConvTranspose3d)

## **Trigger**

Upsample feature map resolutions in generative models, autoencoders, or segmentation decoders via learnable transposed convolution.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, in_channels, height, width)`  
`x = torch.randn(4, 128, 16, 16)`

`# Upsample spatial dimensions 2x`  
`deconv = nn.ConvTranspose2d(`  
    `in_channels=128,`  
    `out_channels=64,`  
    `kernel_size=4,`  
    `stride=2,`  
    `padding=1,`  
`)`  
`output = deconv(x)`

`print(output.shape)  # torch.Size([4, 64, 32, 32])`

## **Minimal Notes**

Transposed convolutions often produce checkerboard artifacts in output images. Using stride=2, kernel\_size=4, and padding=1 yields exact 2× spatial upsampling.

## **Common Bug**

**Issue:** Output dimensions do not match the expected upsampled size or produce checkerboard patterns.

**Cause:** Incorrect pairing of kernel\_size, stride, padding, and output\_padding.

**Quick Fix:** Calculate output shape as (*I*−1)×stride−2×padding+kernel\_size+output\_padding. Alternatively, use nn.Upsample followed by nn.Conv2d.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.ConvTranspose2d.html](https://pytorch.org/docs/stable/generated/torch.nn.ConvTranspose2d.html)

## **Problem**

Apply ReLU Activation (nn.ReLU)

## **Trigger**

Introduce non-linearity by zeroing out negative input values (*f*(*x*)=max(0,*x*)).

## **Snippet**

`import torch`  
`import torch.nn as nn`

`x = torch.tensor([-2.0, -0.5, 0.0, 1.5, 3.0])`

`relu = nn.ReLU(inplace=False)`  
`output = relu(x)`

`print(output)  # tensor([0.0, 0.0, 0.0, 1.5, 3.0])`

## **Minimal Notes**

Setting inplace=True modifies the input tensor in memory to reduce memory usage, but can cause gradient tracking issues if used in skip connections.

## **Common Bug**

**Issue:** RuntimeError: Output with secondary uses was modified inplace

**Cause:** Using inplace=True on a tensor required by residual/skip connections in autograd.

**Quick Fix:** Set inplace=False or instantiate separate activation instances when gradients are tracked across branches.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.ReLU.html](https://pytorch.org/docs/stable/generated/torch.nn.ReLU.html)

## **Problem**

Apply Leaky ReLU Activation (nn.LeakyReLU)

## **Trigger**

Mitigate the "dying ReLU" problem by allowing a small, non-zero gradient (*f*(*x*)=max(*αx*,*x*)) for negative inputs.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`x = torch.tensor([-2.0, -0.5, 0.0, 1.5, 3.0])`

`# Negative slope alpha set to 0.01`  
`leaky_relu = nn.LeakyReLU(negative_slope=0.01)`  
`output = leaky_relu(x)`

`print(output)  # tensor([-0.0200, -0.0050,  0.0000,  1.5000,  3.0000])`

## **Minimal Notes**

Default negative\_slope is 0.01. It preserves gradient flow through inactive neurons during backpropagation.

## **Common Bug**

**Issue:** Unexpectedly large negative activation values destabilizing downstream layers.

**Cause:** Setting negative\_slope too high (e.g., \> 0.2) without adjusting downstream normalization or initialization.

**Quick Fix:** Keep negative\_slope between 0.01 and 0.2.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.LeakyReLU.html](https://pytorch.org/docs/stable/generated/torch.nn.LeakyReLU.html)

## **Problem**

Apply GELU Activation (nn.GELU)

## **Trigger**

Apply smooth, Gaussian Error Linear Unit activation preferred in modern Transformer backbones (e.g., BERT, Vision Transformers).

## **Snippet**

`import torch`  
`import torch.nn as nn`

`x = torch.randn(2, 64)`

`# Modern accurate or fast approximate GELU`  
`gelu = nn.GELU(approximate="none")`  
`output = gelu(x)`

`print(output.shape)  # torch.Size([2, 64])`

## **Minimal Notes**

Setting approximate='tanh' uses a faster approximation 0.5*x*(1+tanh(2/*π*​(*x*\+0.044715*x*3))) suitable for optimization without accuracy degradation.

## **Common Bug**

**Issue:** State dict key mismatch when loading legacy checkpoint weights using GELU approximations.

**Cause:** Discrepancy between standard exact GELU (approximate="none") and approximate variants.

**Quick Fix:** Ensure approximate setting matches the checkpoint's architecture configuration.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.GELU.html](https://pytorch.org/docs/stable/generated/torch.nn.GELU.html)

## **Problem**

Apply SiLU Activation (nn.SiLU)

## **Trigger**

Apply Sigmoid Linear Unit (*f*(*x*)=*x*⋅*σ*(*x*)), also known as Swish, commonly used in modern CNNs (ConvNeXt, EfficientNet) and LLM MLPs (LLaMA).

## **Snippet**

`import torch`  
`import torch.nn as nn`

`x = torch.randn(4, 128)`

`silu = nn.SiLU()`  
`output = silu(x)`

`print(output.shape)  # torch.Size([4, 128])`

## **Minimal Notes**

SiLU is non-monotonic and smooth, outperforming ReLU in deep vision and language models. Supports optional inplace=True.

## **Common Bug**

**Issue:** High memory consumption during backpropagation in deep networks.

**Cause:** Storing intermediate activations for autograd without using inplace operation where safe.

**Quick Fix:** Use nn.SiLU(inplace=True) in sequential modules where inputs are not referenced in skip connections.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.SiLU.html](https://pytorch.org/docs/stable/generated/torch.nn.SiLU.html)

## **Problem**

Apply Softmax Activation (nn.Softmax)

## **Trigger**

Convert unnormalized logits into a probability distribution summing to 1 along a specified dimension.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`logits = torch.randn(2, 5)`

`# Softmax over class dimension (dim=-1)`  
`softmax = nn.Softmax(dim=-1)`  
`probs = softmax(logits)`

`print(probs.sum(dim=-1))  # tensor([1.0000, 1.0000])`

## **Minimal Notes**

Always explicitly specify the dim parameter. Do NOT use nn.Softmax before nn.CrossEntropyLoss, as nn.CrossEntropyLoss expects unnormalized logits.

## **Common Bug**

**Issue:** Poor model performance or vanishing gradients during classification training.

**Cause:** Applying nn.Softmax output directly into nn.CrossEntropyLoss (which applies LogSoftmax internally).

**Quick Fix:** Remove nn.Softmax from the final layer when using nn.CrossEntropyLoss.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.Softmax.html](https://pytorch.org/docs/stable/generated/torch.nn.Softmax.html)

## **Problem**

Apply LogSoftmax Activation (nn.LogSoftmax)

## **Trigger**

Compute log-probabilities directly over logits for numerical stability when using nn.NLLLoss.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`logits = torch.randn(2, 5)`

`# Compute log probabilities along class axis`  
`log_softmax = nn.LogSoftmax(dim=-1)`  
`log_probs = log_softmax(logits)`

`print(log_probs.shape)  # torch.Size([2, 5])`

## **Minimal Notes**

LogSoftmax avoids underflow/overflow problems caused by taking torch.log(torch.softmax(x)). Mathematically equivalent to log(Softmax(*x*)).

## **Common Bug**

**Issue:** Implicit parameter warning or unexpected behavior across batch dimension.

**Cause:** Omitting the dim argument when initializing nn.LogSoftmax().

**Quick Fix:** Always explicitly supply the target axis, typically dim=-1.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.LogSoftmax.html](https://pytorch.org/docs/stable/generated/torch.nn.LogSoftmax.html)

## **Problem**

Apply Max Pooling (nn.MaxPool2d)

## **Trigger**

Downsample spatial feature maps by extracting the maximum value within a sliding window.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, channels, height, width)`  
`x = torch.randn(2, 64, 32, 32)`

`# Halve spatial dimensions (32x32 -> 16x16)`  
`pool = nn.MaxPool2d(kernel_size=2, stride=2)`  
`output = pool(x)`

`print(output.shape)  # torch.Size([2, 64, 16, 16])`

## **Minimal Notes**

stride defaults to kernel\_size if not specified. Max pooling provides translation invariance but discards fine spatial details.

## **Common Bug**

**Issue:** Output spatial dimensions are smaller than intended due to floor division during rounding.

**Cause:** Non-even spatial dimensions combined with default ceil\_mode=False.

**Quick Fix:** Set ceil\_mode=True to use ceiling instead of floor for computing output shapes.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.MaxPool2d.html](https://pytorch.org/docs/stable/generated/torch.nn.MaxPool2d.html)

## **Problem**

Apply Average Pooling (nn.AvgPool2d)

## **Trigger**

Downsample spatial feature maps by computing the mean value within a sliding local window.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, channels, height, width)`  
`x = torch.randn(2, 64, 32, 32)`

`pool = nn.AvgPool2d(kernel_size=2, stride=2, count_include_pad=False)`  
`output = pool(x)`

`print(output.shape)  # torch.Size([2, 64, 16, 16])`

## **Minimal Notes**

Smooths spatial features compared to MaxPool2d. Set count\_include\_pad=False to prevent padded zero values from skewing average calculations along boundaries.

## **Common Bug**

**Issue:** Artificially low values along image edges when using padding.

**Cause:** Default count\_include\_pad=True includes zero-padded border regions in the division factor.

**Quick Fix:** Pass count\_include\_pad=False when instantiating nn.AvgPool2d.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.AvgPool2d.html](https://pytorch.org/docs/stable/generated/torch.nn.AvgPool2d.html)

## **Problem**

Apply Adaptive Average Pooling (nn.AdaptiveAvgPool2d)

## **Trigger**

Force feature maps to a fixed spatial target size (*Hout*​,*Wout*​) regardless of input tensor dimensions.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Variable spatial input size`  
`x = torch.randn(2, 512, 14, 14)`

`# Force spatial output to (1, 1) for global average pooling`  
`gap = nn.AdaptiveAvgPool2d(output_size=(1, 1))`  
`output = gap(x)`

`print(output.shape)  # torch.Size([2, 512, 1, 1])`

## **Minimal Notes**

Automatically computes dynamic stride and kernel sizes. Frequently used as a classifier neck (Global Average Pooling) to accept arbitrary input image resolutions.

## **Common Bug**

**Issue:** RuntimeError when passing None as output target size incorrectly.

**Cause:** Misunderstanding how None acts in tuple definitions (passing None preserves the original dimension, but passing invalid objects breaks instantiation).

**Quick Fix:** Use (1, 1\) for standard global average pooling, or (None, 7\) to preserve original height while adapting width to 7\.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.AdaptiveAvgPool2d.html](https://pytorch.org/docs/stable/generated/torch.nn.AdaptiveAvgPool2d.html)

## **Problem**

Apply Adaptive Max Pooling (nn.AdaptiveMaxPool2d)

## **Trigger**

Force feature maps to a fixed spatial target size (*Hout*​,*Wout*​) by extracting maximum values dynamically.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`x = torch.randn(2, 256, 28, 28)`

`# Dynamically reduce spatial dimensions to (7, 7)`  
`adaptive_max = nn.AdaptiveMaxPool2d(output_size=(7, 7))`  
`output = adaptive_max(x)`

`print(output.shape)  # torch.Size([2, 256, 7, 7])`

## **Minimal Notes**

Can optionally return max indices along with pooled values by setting return\_indices=True, which is useful for nn.MaxUnpool2d.

## **Common Bug**

**Issue:** ValueError: too many values to unpack when calling forward.

**Cause:** Expecting a single tensor output while return\_indices=True was passed during layer construction.

**Quick Fix:** Unpack both tensors: output, indices \= adaptive\_max(x).

## **Official Documentation URL**

## **Problem**

Apply Batch Normalization (nn.BatchNorm1d / nn.BatchNorm2d)

## **Trigger**

Normalize channel activations across the batch dimension to accelerate training stability in convolutional or dense networks.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# 2D BatchNorm input: (batch_size, num_features/channels, height, width)`  
`x = torch.randn(8, 64, 32, 32)`

`bn = nn.BatchNorm2d(num_features=64)`  
`output = bn(x)`

`print(output.shape)  # torch.Size([8, 64, 32, 32])`

## **Minimal Notes**

Maintains running mean and variance during training for use during evaluation (model.eval()). Requires batch size \>1 during training to avoid zero-variance division errors.

## **Common Bug**

**Issue:** ValueError: Expected more than 1 value per channel when training, got input size torch.Size(\[1, C, H, W\])

**Cause:** Passing a batch size of 1 in training mode (model.train()).

**Quick Fix:** Drop last incomplete batch in DataLoader(drop\_last=True) or switch to nn.GroupNorm / nn.LayerNorm.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.BatchNorm2d.html](https://pytorch.org/docs/stable/generated/torch.nn.BatchNorm2d.html)

## **Problem**

Apply Layer Normalization (nn.LayerNorm)

## **Trigger**

Normalize features across channel/embedding dimensions independently for each individual sample (standard in Transformers and sequence models).

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, sequence_length, feature_dim)`  
`x = torch.randn(16, 50, 768)`

`# Normalize over final feature dimension (768)`  
`ln = nn.LayerNorm(normalized_shape=768)`  
`output = ln(x)`

`print(output.shape)  # torch.Size([16, 50, 768])`

## **Minimal Notes**

Operates independently of batch size, making it suitable for online inference and small batch training. normalized\_shape must match the trailing dimensions of the input tensor.

## **Common Bug**

**Issue:** RuntimeError: Given normalized\_shape=\[768\], expected input with shape \[\*, 768\], but got input of shape \[...\]

**Cause:** normalized\_shape mismatch with trailing input tensor dimensions.

**Quick Fix:** Pass normalized\_shape matching x.shape\[-1:\] or list/tuple of target trailing dimensions.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.LayerNorm.html](https://pytorch.org/docs/stable/generated/torch.nn.LayerNorm.html)

## **Problem**

Apply Group Normalization (nn.GroupNorm)

## **Trigger**

Normalize features across divided groups of channels per sample, providing batch-size-independent normalization for vision models.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, channels, height, width)`  
`x = torch.randn(4, 32, 64, 64)`

`# Divide 32 channels into 8 groups (4 channels per group)`  
`gn = nn.GroupNorm(num_groups=8, num_channels=32)`  
`output = gn(x)`

`print(output.shape)  # torch.Size([4, 32, 64, 64])`

## **Minimal Notes**

num\_channels must be strictly divisible by num\_groups. Acts as LayerNorm when num\_groups=1 and InstanceNorm when num\_groups=num\_channels.

## **Common Bug**

**Issue:** ValueError: num\_channels should be divisible by num\_groups

**Cause:** Setting num\_groups to a value that does not evenly divide num\_channels.

**Quick Fix:** Adjust num\_groups such that num\_channels % num\_groups \== 0\.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.GroupNorm.html](https://pytorch.org/docs/stable/generated/torch.nn.GroupNorm.html)

## **Problem**

Apply Instance Normalization (nn.InstanceNorm2d)

## **Trigger**

Normalize features independently per channel per sample, commonly used in style transfer and generative adversarial networks (GANs).

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, channels, height, width)`  
`x = torch.randn(2, 64, 128, 128)`

`# Set affine=True if learnable gamma/beta parameters are required`  
`inst_norm = nn.InstanceNorm2d(num_features=64, affine=True)`  
`output = inst_norm(x)`

`print(output.shape)  # torch.Size([2, 64, 128, 128])`

## **Minimal Notes**

Does not track running statistics across batches by default (track\_running\_stats=False). Learnable affine parameters (*γ*,*β*) are disabled by default unless affine=True.

## **Common Bug**

**Issue:** Model fails to learn dynamic scale and shift transformations.

**Cause:** affine=False by default in nn.InstanceNorm2d, leaving gamma and beta fixed at 1 and 0\.

**Quick Fix:** Explicitly pass affine=True during layer initialization if learnable parameters are needed.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.InstanceNorm2d.html](https://pytorch.org/docs/stable/generated/torch.nn.InstanceNorm2d.html)

## **Problem**

Apply Dropout (nn.Dropout)

## **Trigger**

Zero out elements randomly during training with probability *p* to prevent feature co-adaptation and overfitting.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`x = torch.ones(2, 10)`

`# Dropout probability p=0.5`  
`dropout = nn.Dropout(p=0.5)`

`dropout.train()`  
`print(dropout(x))  # Values scaled by 1/(1-p) = 2.0 or 0.0`

`dropout.eval()`  
`print(dropout(x))  # Passes through unchanged`

## **Minimal Notes**

Outputs are scaled by 1−*p*1​ during training so that the expected sum remains unchanged. Has no effect when in evaluation mode (model.eval()).

## **Common Bug**

**Issue:** Dropout continues zeroing out activations during testing or inference.

**Cause:** Forgetting to call model.eval() before running inference.

**Quick Fix:** Set model.eval() prior to validation or deployment execution.

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.Dropout.html](https://pytorch.org/docs/stable/generated/torch.nn.Dropout.html)

## **Problem**

Apply Spatial Dropout (nn.Dropout2d)

## **Trigger**

Zero out entire feature map channels randomly rather than individual pixels to enforce channel-level feature independence in CNNs.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`# Input shape: (batch_size, channels, height, width)`  
`x = torch.ones(2, 4, 8, 8)`

`spatial_dropout = nn.Dropout2d(p=0.5)`  
`spatial_dropout.train()`

`output = spatial_dropout(x)`  
`print(output[0, :, 0, 0])  # Entire 2D channels are set to 0 or scaled`

## **Minimal Notes**

Expects 4D input tensors (N, C, H, W). If a channel is selected for dropout, the entire 2D feature map for that channel is zeroed out.

## **Common Bug**

**Issue:** Passing 2D or 3D tensors into nn.Dropout2d.

**Cause:** Input tensor format does not meet the expected 4D shape requirement (N, C, H, W).

**Quick Fix:** Use standard nn.Dropout for 1D/2D tensors or reshape inputs to 4D before applying nn.Dropout2d.

## **Problem**

Manage Dynamic Layers (nn.ModuleList)

## **Trigger**

Store submodules in a Python list structure while properly registering their parameters with PyTorch autograd.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`class DynamicMLP(nn.Module):`

  `def __init__(self, sizes):`  
    `super().__init__()`  
    `# Correct parameter registration for list of modules`  
    `self.layers = nn.ModuleList(`  
        `[nn.Linear(sizes[i], sizes[i + 1]) for i in range(len(sizes) - 1)]`  
    `)`

  `def forward(self, x):`  
    `for layer in self.layers:`  
      `x = torch.relu(layer(x))`  
    `return x`

`model = DynamicMLP([64, 128, 256, 10])`  
`x = torch.randn(8, 64)`  
`print(model(x).shape)  # torch.Size([8, 10])`

## **Minimal Notes**

Standard Python list objects do not register child submodules or parameters when assigned as module attributes. nn.ModuleList does not implement its own forward() method.

## **Common Bug**

**Issue:** Model parameters inside a list are missing from model.parameters() and optimizer state, so they do not update during training.

**Cause:** Storing child modules inside a native Python list self.layers \= \[...\] instead of nn.ModuleList.

**Quick Fix:** Wrap module lists using self.layers \= nn.ModuleList(...).

## **Official Documentation URL**

[https://pytorch.org/docs/stable/generated/torch.nn.ModuleList.html](https://pytorch.org/docs/stable/generated/torch.nn.ModuleList.html)

## **Trigger**

`import torch`

**Issue:** Parameters are not moved to GPU when calling model.to("cuda").

**Cause:** Storing child modules inside standard Python dict attributes rather than nn.ModuleDict.

**Quick Fix:** Use self.branches \= nn.ModuleDict({...}) to ensure parameters register correctly.

## **Problem**

Register Learnable Parameters (nn.ParameterList / nn.ParameterDict)

## **Trigger**

Store collections of raw learnable tensors (nn.Parameter) in list or dictionary formats with autograd tracking.

## **Snippet**

`import torch`  
`import torch.nn as nn`

`class CustomWeights(nn.Module):`

  `def __init__(self, num_params, dim):`  
    `super().__init__()`  
    `# Register list of standalone raw weight tensors`  
    `self.params = nn.ParameterList(`  
        `[nn.Parameter(torch.randn(dim, dim)) for _ in range(num_params)]`  
    `)`

  `def forward(self, x):`  
    `for p in self.params:`  
      `x = torch.matmul(x, p)`  
    `return x`

`model = CustomWeights(num_params=3, dim=16)`  
`x = torch.randn(4, 16)`

## **Minimal Notes**

nn.ParameterList and nn.ParameterDict hold raw nn.Parameter instances, whereas nn.ModuleList holds complete nn.Module instances.

## **Common Bug**

**Issue:** Plain tensors added to Python lists are ignored by optimizers and do not compute gradients.

**Cause:** Assigning non-parameter tensors or using non-PyTorch containers for custom weight collections.

**Quick Fix:** Wrap tensors as nn.Parameter(tensor) and store them inside nn.ParameterList or nn.ParameterDict.
