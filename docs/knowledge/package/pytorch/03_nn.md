## **Task**

Create Fully Connected Layer (nn.Linear)

## **Problem Solved**

Applies a linear transformation to input data using learnable weight and bias matrices.

## **Mental Trigger**

I need a learnable layer that projects feature vectors into a different dimensional space.

## **Syntax**

torch.nn.Linear(in\_features, out\_features, bias=True, device=None, dtype=None)

## **Important Parameters**

> * **in\_features** (*int*): Size of each input sample.  
> * **out\_features** (*int*): Size of each output sample.  
> * **bias** (*bool*, optional): If False, the layer will not learn an additive bias. Default: True.

## **Return Value**

Returns a torch.nn.Linear module instance. When called with input tensor of shape (\*, in\_features), outputs tensor of shape (\*, out\_features).

## **Example**

import torch  
import torch.nn as nn

linear\_layer \= nn.Linear(in\_features=128, out\_features=64)  
x \= torch.randn(32, 128\)  
output \= linear\_layer(x)

print(f"Output shape: {output.shape}")

## **Use When**

> * Mapping latent embeddings or extracted features to classification logits.  
> * Building multi-layer perceptrons (MLPs).  
> * Projecting hidden states between transformer layers.

## **Avoid When**

> * Processing raw 2D spatial image structures where translation invariance is needed (use nn.Conv2d instead).

## **Gotchas**

> * Input tensor last dimension must match in\_features exactly or a RuntimeError will occur.  
> * Initializing heavy nn.Linear modules without device="meta" can exhaust host RAM for massive architectures.  
> * Biases default to Kaiming uniform initialization, which may require manual re-initialization for specific loss landscapes.

## **Performance Notes**

> * nn.Linear leverages optimized GEMM calls (BLAS/cuBLAS).  
> * Dimensional alignments to multiples of 8 or 16 optimize GPU Tensor Core utilization.

## **Related APIs**

> * torch.nn.functional.linear  
> * torch.nn.LazyLinear

## **Framework Migration Notes**

Maps cleanly from Keras/TensorFlow. Weight shapes in PyTorch are stored as (out\_features, in\_features), transposed relative to TensorFlow.

## **TensorFlow Equivalent**

nn.Linear → tf.keras.layers.Dense

## **Version Compatibility**

No significant changes in modern PyTorch releases.

## **Search Metadata**

> * **Aliases**: Dense layer, Fully connected layer, Linear transformation, Affine projection  
> * **Common Search Terms**: pytorch linear layer, fc layer pytorch, nn.linear usage  
> * **Keywords**: linear, dense, fully\_connected, affine, projection  
> * **Frequently Confused With**: nn.LazyLinear (which defers input dimension specification)

## **Task**

Create Lazy Linear Layer (nn.LazyLinear)

## **Problem Solved**

Defers in\_features initialization until the first forward pass, enabling automatic shape inference.

## **Mental Trigger**

I want a linear layer where the input dimension is automatically detected from the input tensor shape during runtime.

## **Syntax**

torch.nn.LazyLinear(out\_features, bias=True, device=None, dtype=None)

## **Important Parameters**

> * **out\_features** (*int*): Size of each output sample.  
> * **bias** (*bool*, optional): If False, the layer will not learn an additive bias. Default: True.

## **Return Value**

Returns an uninitialized torch.nn.LazyLinear module. Parameters are instantiated on the first forward pass.

## **Example**

import torch  
import torch.nn as nn

lazy\_layer \= nn.LazyLinear(out\_features=10)  
x \= torch.randn(16, 256\)

\# Parameters are uninitialized before forward pass  
output \= lazy\_layer(x)  
print(f"Weight shape after forward pass: {lazy\_layer.weight.shape}")

## **Use When**

> * Connecting convolutional trunks to dense heads where calculating flatten dimensions manually is tedious.  
> * Prototyping architectures rapidly.

## **Avoid When**

> * Instantiating optimizers before executing at least one dummy forward pass through the network.  
> * Loading state dicts directly into uninitialized modules.

## **Gotchas**

> * Passing model.parameters() to an optimizer *before* running a forward pass will omit lazy layer parameters from optimization.  
> * Model checkpointing (state\_dict()) fails or produces uninitialized parameter warnings if saved before the first forward call.  
> * Unexpected input shape changes across forward passes after initialization trigger runtime assertion errors.

## **Performance Notes**

> * Introduces a small overhead on the very first forward execution while parameter tensors are allocated. Subsequent calls run at standard nn.Linear speed.

## **Related APIs**

> * torch.nn.Linear  
> * torch.nn.modules.lazy.LazyModuleMixin

## **Framework Migration Notes**

Mimics Keras behavior where layer input shapes do not need explicit declaration upon instantiation.

## **TensorFlow Equivalent**

nn.LazyLinear → tf.keras.layers.Dense (with input\_shape omitted)

## **Version Compatibility**

No significant changes in modern PyTorch releases.

## **Search Metadata**

> * **Aliases**: Auto-shape Linear, Lazy Dense Layer  
> * **Common Search Terms**: pytorch lazy linear, infer input shape linear layer  
> * **Keywords**: lazy, linear, shape\_inference, dynamic\_initialization

## **Task**

Create 1D Convolution Layer (nn.Conv1d)

## **Problem Solved**

Extracts local spatial or temporal features across 1D sequences or signal channels.

## **Mental Trigger**

I need to apply sliding filter kernels across sequential data like audio waveforms or time series.

## **Syntax**

torch.nn.Conv1d(in\_channels, out\_channels, kernel\_size, stride=1, padding=0, dilation=1, groups=1, bias=True, padding\_mode='zeros')

## **Important Parameters**

> * **in\_channels** (*int*): Number of channels in the input signal.  
> * **out\_channels** (*int*): Number of channels produced by the convolution.  
> * **kernel\_size** (*int* or *tuple*): Size of the convolving kernel.  
> * **stride** (*int* or *tuple*, optional): Stride of the convolution. Default: 1\.  
> * **padding** (*int*, *tuple* or *str*, optional): Zero-padding added to both sides of input. Default: 0\.

## **Return Value**

Returns a torch.nn.Conv1d layer. Output shape is (N, C\_out, L\_out).

## **Example**

import torch  
import torch.nn as nn

conv1d\_layer \= nn.Conv1d(in\_channels=16, out\_channels=32, kernel\_size=3, stride=1, padding=1)  
\# Input shape: Batch=8, Channels=16, Sequence Length=100  
x \= torch.randn(8, 16, 100\)  
output \= conv1d\_layer(x)

print(f"Output shape: {output.shape}")

## **Use When**

> * Feature extraction from audio samples, bio-signals (ECG/EEG), or natural language embeddings formatted as sequence channels.

## **Avoid When**

> * Sequence lengths are highly dynamic and global context is required across long distances without local structure (use Transformers instead).

## **Gotchas**

> * Input shape must strictly follow (Batch, Channels, Length), not (Batch, Length, Channels).  
> * Setting padding='same' is only supported when stride=1.  
> * High dilation values drastically increase memory access footprints without adding parameters.

## **Performance Notes**

> * Utilizes cuDNN optimized 1D implicit GEMM routines on GPU hardware.

## **Related APIs**

> * torch.nn.functional.conv1d  
> * torch.nn.Conv2d

## **Framework Migration Notes**

Keras Conv1D expects (Batch, Steps, Channels). PyTorch requires channel dimension first: (Batch, Channels, Steps).

## **TensorFlow Equivalent**

nn.Conv1d → tf.keras.layers.Conv1D

## **Version Compatibility**

No significant changes in modern PyTorch releases.

## **Search Metadata**

> * **Aliases**: 1D Convolution, Temporal Convolution  
> * **Common Search Terms**: pytorch conv1d, 1d conv time series, conv1d shape pytorch  
> * **Keywords**: conv1d, temporal, sequence, signal, convolution  
> * **Frequently Confused With**: nn.Conv2d

## **Task**

Create 2D Convolution Layer (nn.Conv2d)

## **Problem Solved**

Extracts spatial hierarchies and localized features from 2D structural arrays such as images or spectrograms.

## **Mental Trigger**

I need sliding 2D kernel filters to extract visual features from multi-channel images.

## **Syntax**

torch.nn.Conv2d(in\_channels, out\_channels, kernel\_size, stride=1, padding=0, dilation=1, groups=1, bias=True, padding\_mode='zeros')

## **Important Parameters**

> * **in\_channels** (*int*): Number of channels in the input image.  
> * **out\_channels** (*int*): Number of channels produced by the convolution.  
> * **kernel\_size** (*int* or *tuple*): Size of the convolving kernel.  
> * **stride** (*int* or *tuple*, optional): Stride of the convolution. Default: 1\.  
> * **padding** (*int*, *tuple* or *str*, optional): Padding added to input borders. Default: 0\.

## **Return Value**

Returns a torch.nn.Conv2d instance. Accepts input shape (N, C\_in, H\_in, W\_in) and outputs (N, C\_out, H\_out, W\_out).

## **Example**

import torch  
import torch.nn as nn

conv2d\_layer \= nn.Conv2d(in\_channels=3, out\_channels=64, kernel\_size=3, stride=2, padding=1)  
\# Input: Batch=4, RGB Channels=3, Height=224, Width=224  
x \= torch.randn(4, 3, 224, 224\)  
output \= conv2d\_layer(x)

print(f"Output shape: {output.shape}")

## **Use When**

> * Building vision backbones (e.g., ResNet, YOLO) for image classification, detection, and segmentation tasks.

## **Avoid When**

> * Inputs are flat unstructured tabular data vectors.

## **Gotchas**

> * Input shape must be (N, C, H, W) \- channels-first layout. Passing channels-last tensors (N, H, W, C) without layout conversion breaks channel math.  
> * Setting groups to in\_channels performs depthwise convolution; ensure out\_channels is a multiple of in\_channels.  
> * Non-matching padding and kernel dimensions can alter spatial resolution unintentionally.

## **Performance Notes**

> * Using memory\_format=torch.channels\_last on modern Nvidia GPUs accelerates nn.Conv2d by leveraging Tensor Cores.

## **Related APIs**

> * torch.nn.functional.conv2d  
> * torch.nn.Conv3d

## **Framework Migration Notes**

PyTorch defaults to channels-first (N, C, H, W) format, whereas TensorFlow defaults to channels-last (N, H, W, C).

## **TensorFlow Equivalent**

nn.Conv2d → tf.keras.layers.Conv2D

## **Version Compatibility**

No significant changes in modern PyTorch releases.

## **Task**

Create 3D Convolution Layer (nn.Conv3d)

## **Problem Solved**

Applies 3D convolution kernels over volumetric or spatiotemporal inputs (e.g., video clips or 3D medical scans).

## **Mental Trigger**

I need sliding filters across three dimensions simultaneously (like depth/time, height, and width).

## **Syntax**

torch.nn.Conv3d(in\_channels, out\_channels, kernel\_size, stride=1, padding=0, dilation=1, groups=1, bias=True, padding\_mode='zeros')

## **Important Parameters**

> * **in\_channels** (*int*): Number of channels in the input tensor.  
> * **out\_channels** (*int*): Number of channels produced by the convolution.  
> * **kernel\_size** (*int* or *tuple*): Size of the 3D convolving kernel (D, H, W).  
> * **stride** (*int* or *tuple*, optional): Stride across 3 dimensions. Default: 1\.  
> * **padding** (*int*, *tuple* or *str*, optional): Implicit padding on all three sides. Default: 0\.

## **Return Value**

Returns a torch.nn.Conv3d module. Input shape: (N, C\_in, D\_in, H\_in, W\_in); Output shape: (N, C\_out, D\_out, H\_out, W\_out).

## **Example**

import torch  
import torch.nn as nn

conv3d\_layer \= nn.Conv3d(in\_channels=1, out\_channels=16, kernel\_size=(3, 3, 3), padding=1)  
\# Input: Batch=2, Channels=1, Depth/Frames=16, Height=64, Width=64  
x \= torch.randn(2, 1, 16, 64, 64\)  
output \= conv3d\_layer(x)

print(f"Output shape: {output.shape}")

## **Use When**

> * Extracting features from 3D CT/MRI medical scans or processing video sequences with temporal depth.

## **Avoid When**

> * Spatial dimensions can be processed frame-by-frame using 2D convolutions with pooled temporal aggregation, saving GPU memory.

## **Gotchas**

> * Extremely high GPU memory usage due to 5D activations; keep batch sizes and channel counts moderate.  
> * Parameter shapes and strides require 3-element tuples if non-square dimensions are used.

## **Performance Notes**

> * High VRAM consumption. Mixed precision (torch.cuda.amp) is strongly recommended to avoid GPU out-of-memory errors.

## **Related APIs**

> * torch.nn.functional.conv3d  
> * torch.nn.Conv2d

## **Framework Migration Notes**

Matches TensorFlow Conv3D concept, but requires input format (N, C, D, H, W).

## **TensorFlow Equivalent**

nn.Conv3d → tf.keras.layers.Conv3D

## **Version Compatibility**

No significant changes in modern PyTorch releases.

## **Task**

Create Transposed Convolution Layer (nn.ConvTranspose2d / nn.ConvTranspose3d)

## **Problem Solved**

Applies transposed convolution (fractionally strided convolution) to upsample spatial or volumetric feature maps.

## **Mental Trigger**

I need a learnable upsampling layer to increase spatial resolution in decoders or generative models.

## **Syntax**

torch.nn.ConvTranspose2d(in\_channels, out\_channels, kernel\_size, stride=1, padding=0, output\_padding=0, groups=1, bias=True, dilation=1)

## **Important Parameters**

> * **in\_channels** (*int*): Number of channels in the input.  
> * **out\_channels** (*int*): Number of output channels.  
> * **kernel\_size** (*int* or *tuple*): Size of the transposed convolution kernel.  
> * **stride** (*int* or *tuple*, optional): Upsampling factor/stride. Default: 1\.  
> * **output\_padding** (*int* or *tuple*, optional): Additional size added to one side of the output shape. Default: 0\.

## **Return Value**

Returns a transposed convolution module (nn.ConvTranspose2d or nn.ConvTranspose3d). Upsamples spatial inputs according to kernel and stride specifications.

## **Example**

import torch  
import torch.nn as nn

upsample\_layer \= nn.ConvTranspose2d(in\_channels=64, out\_channels=32, kernel\_size=4, stride=2, padding=1)  
\# Input spatial dimension: 16x16  
x \= torch.randn(2, 64, 16, 16\)  
output \= upsample\_layer(x)

print(f"Output shape (doubled resolution): {output.shape}")

## **Use When**

> * Decoder architectures in U-Net, Autoencoders, GAN generators, and semantic segmentation heads.

## **Avoid When**

> * Avoiding checkerboard artifacts in generated images is crucial (use nn.Upsample followed by nn.Conv2d instead).

## **Gotchas**

> * output\_padding is only used to resolve shape ambiguities when stride \> 1; it does not add zero padding to the input itself.  
> * Susceptible to checkerboard artifacts if kernel size is not divisible by stride.

## **Performance Notes**

> * Slightly higher memory bandwidth requirements compared to standard bilinear upsampling layers.

## **Related APIs**

> * torch.nn.Conv2d  
> * torch.nn.Upsample

## **Framework Migration Notes**

Equivalent to Conv2DTranspose in TensorFlow/Keras.

## **TensorFlow Equivalent**

nn.ConvTranspose2d → tf.keras.layers.Conv2DTranspose  
nn.ConvTranspose3d → tf.keras.layers.Conv3DTranspose

## **Version Compatibility**

No significant changes in modern PyTorch releases.

> * **Common Search Terms**: pytorch convtranspose2d, deconv layer pytorch, upsampling conv  
> * **Keywords**: convtranspose, deconvolution, upsampling, generator, unet

## **Task**

Apply ReLU Activation (nn.ReLU)

## **Problem Solved**

Applies element-wise Rectified Linear Unit activation function *f*(*x*)=max(0,*x*) to introduce non-linearity.

## **Mental Trigger**

I need a standard, fast non-linear activation function that zeroes out negative values.

## **Syntax**

torch.nn.ReLU(inplace=False)

## **Important Parameters**

> * **inplace** (*bool*, optional): If True, modifies the input tensor directly to conserve memory. Default: False.

## **Return Value**

Returns an nn.ReLU module. Tensor dimensions remain identical to input.

## **Example**

import torch  
import torch.nn as nn

relu \= nn.ReLU(inplace=True)  
x \= torch.tensor(\[-2.0, \-0.5, 0.0, 1.5, 3.0\])  
output \= relu(x)

print(f"Output: {output}")

## **Use When**

> * Hidden layers in deep convolutional networks and MLPs.  
> * Seeking maximum compute efficiency with zero floating-point transcendental function costs.

## **Avoid When**

> * Experiencing "dying ReLU" issues where neurons saturate at 0 permanent gradients during training.

## **Gotchas**

> * Using inplace=True can break Autograd graph computation if the input tensor is needed for gradient calculations in a prior residual path.

## **Performance Notes**

> * Extremely fast execution on hardware; executed as simple thresholding (max(0,*x*)).

## **Related APIs**

> * torch.nn.functional.relu  
> * torch.nn.LeakyReLU

## **Framework Migration Notes**

Direct one-to-one equivalent with tf.keras.layers.ReLU.

## **TensorFlow Equivalent**

nn.ReLU → tf.keras.layers.ReLU

## **Version Compatibility**

No significant changes in modern PyTorch releases.

## **Task**

Apply Leaky ReLU Activation (nn.LeakyReLU)

## **Problem Solved**

Applies element-wise activation function *f*(*x*)=max(*x*,negative\_slope⋅*x*) allowing small non-zero gradients for negative inputs.

## **Mental Trigger**

I want a ReLU activation that prevents inactive neurons from dying by providing a small slope for negative values.

## **Syntax**

torch.nn.LeakyReLU(negative\_slope=0.01, inplace=False)

## **Important Parameters**

> * **negative\_slope** (*float*, optional): Controls the angle of the negative slope. Default: 0.01.  
> * **inplace** (*bool*, optional): Performs operation in-place. Default: False.

## **Return Value**

Returns an nn.LeakyReLU module instance. Output tensor matches input shape.

## **Example**

import torch  
import torch.nn as nn

leaky\_relu \= nn.LeakyReLU(negative\_slope=0.1)  
x \= torch.tensor(\[-2.0, \-1.0, 0.0, 2.0\])  
output \= leaky\_relu(x)

print(f"Output: {output}")

## **Use When**

> * Training deep networks or GAN discriminators prone to dying neuron problems under standard ReLU.

## **Avoid When**

> * Canonical architecture specifications explicitly mandate standard ReLU or GELU activations.

## **Gotchas**

> * Setting negative\_slope too high converts the layer into a near-linear transformation.  
> * Inplace operations can cause backpropagation graph issues in complex computational DAGs.

## **Performance Notes**

> * Minimal overhead over standard ReLU; adds one multiply-scalar step for negative values.

## **Related APIs**

> * torch.nn.functional.leaky\_relu  
> * torch.nn.PReLU

## **Framework Migration Notes**

Identical behavior to Keras LeakyReLU.

## **TensorFlow Equivalent**

## **Version Compatibility**

No significant changes in modern PyTorch releases.

## **Task**

Apply GELU Activation (nn.GELU)

## **Problem Solved**

Applies Gaussian Error Linear Unit activation, weighting inputs by their value rather than gating strictly by sign.

## **Mental Trigger**

I need the standard smooth activation function used in modern Transformer architectures like BERT and GPT.

## **Syntax**

torch.nn.GELU(approximate='none')

## **Important Parameters**

> * **approximate** (*str*, optional): Approximation algorithm to use ('none' or 'tanh'). Default: 'none'.

## **Return Value**

Returns an nn.GELU activation module.

## **Example**

import torch  
import torch.nn as nn

gelu \= nn.GELU(approximate='tanh')  
x \= torch.randn(2, 4\)  
output \= gelu(x)

print(f"Output:\\n{output}")

## **Use When**

> * Constructing modern Transformer Feed-Forward Networks (FFN) and Vision Transformers (ViT).

## **Avoid When**

> * Deploying on ultra-low-power edge hardware lacking fast transcendental GPU kernel implementations.

## **Gotchas**

> * Setting approximate='tanh' produces slight numerical differences compared to 'none'. Ensure consistency across training and inference engines.

## **Performance Notes**

> * PyTorch utilizes fused CUDA implementation for GELU. approximate='tanh' provides a slight speed advantage on older GPU architectures.

## **Related APIs**

> * torch.nn.functional.gelu  
> * torch.nn.SiLU

## **Framework Migration Notes**

Equivalent to tf.keras.activations.gelu.

## **TensorFlow Equivalent**

## **Version Compatibility**

No significant changes in modern PyTorch releases.

## **Problem Solved**

Holds submodules in a list, ensuring parameters are properly registered with the parent nn.Module.

torch.nn.ModuleList(modules=None)

## **Important Parameters**

> * **modules** (*iterable*, optional): An iterable of modules to add to the list.

## **Example**

import torch  
import torch.nn as nn

class DynamicNet(nn.Module):  
    def \_\_init\_\_(self, num\_layers=3):  
        super().\_\_init\_\_()  
        self.layers \= nn.ModuleList(\[nn.Linear(64, 64\) for \_ in range(num\_layers)\])  
          
    def forward(self, x):  
        for layer in self.layers:  
            x \= layer(x)  
        return x

model \= DynamicNet(num\_layers=4)  
x \= torch.randn(2, 64\)  
print(f"Output shape: {model(x).shape}")

> * **key** (*Tensor*): Key tensor of shape (N, ..., S, E).

## **Task**

Build Vanilla RNN (nn.RNN)

## **Problem Solved**

Applies a multi-layer Elman Recurrent Neural Network (RNN) with tanh or ReLU non-linearity to sequential inputs.

## **Mental Trigger**

I need a basic recurrent neural network baseline layer to process sequence data step-by-step.

## **Syntax**

torch.nn.RNN(input\_size, hidden\_size, num\_layers=1, nonlinearity='tanh', bias=True, batch\_first=False, dropout=0.0, bidirectional=False)

## **Important Parameters**

> * **input\_size** (*int*): Number of expected features in input *x*.  
> * **hidden\_size** (*int*): Number of features in hidden state *h*.  
> * **num\_layers** (*int*, optional): Number of stacked recurrent layers. Default: 1\.  
> * **batch\_first** (*bool*, optional): If True, input shape is (batch, seq, feature). Default: False.  
> * **bidirectional** (*bool*, optional): If True, becomes a bidirectional RNN. Default: False.

## **Return Value**

Returns tuple (output, h\_n) where output contains hidden states across time steps, and h\_n holds the final hidden state.

## **Example**

import torch  
import torch.nn as nn

rnn \= nn.RNN(input\_size=10, hidden\_size=20, num\_layers=2, batch\_first=True)  
\# Input: Batch=3, Seq\_Len=5, Feature\_Dim=10  
x \= torch.randn(3, 5, 10\)  
output, h\_n \= rnn(x)

print(f"Sequence output shape: {output.shape}")  
print(f"Final hidden state shape: {h\_n.shape}")

## **Use When**

> * Lightweight baseline sequence modeling tasks with very short sequence dependencies.

## **Avoid When**

> * Long sequential context learning where vanishing/exploding gradients severely harm vanilla RNNs (use LSTM/GRU or Transformers instead).

## **Gotchas**

> * Default tensor ordering expects (seq\_len, batch, feature). Set batch\_first=True if using standard batch-first layouts.

## **Performance Notes**

> * Fast cuDNN execution; however, sequential time dependency restricts parallel hardware acceleration compared to Transformers.

Instantiates a full end-to-end Sequence-to-Sequence Transformer model architecture combining both Encoder and Decoder stacks.

## **Mental Trigger**

I need a complete standard Transformer model (Attention Is All You Need architecture) out of the box.

## **Syntax**

torch.nn.Transformer(d\_model=512, nhead=8, num\_encoder\_layers=6, num\_decoder\_layers=6, dim\_feedforward=2048, dropout=0.1, activation=F.relu, custom\_encoder=None, custom\_decoder=None, layer\_norm\_eps=1e-05, batch\_first=False, norm\_first=False)

## **Important Parameters**

> * **d\_model** (*int*, optional): Dimension of feature vectors. Default: 512\.  
> * **nhead** (*int*, optional): Number of attention heads. Default: 8\.  
> * **num\_encoder\_layers** (*int*, optional): Stacked encoder count. Default: 6\.  
> * **num\_decoder\_layers** (*int*, optional): Stacked decoder count. Default: 6\.  
> * **batch\_first** (*bool*, optional): Sets shape order to (batch, seq, feature) if True. Default: False.

## **Return Value**

Returns a full nn.Transformer module instance.

## **Example**

import torch  
import torch.nn as nn

transformer \= nn.Transformer(  
    d\_model=64, nhead=4, num\_encoder\_layers=2, num\_decoder\_layers=2, batch\_first=True  
)

src \= torch.randn(2, 10, 64\) \# Source sequence  
tgt \= torch.randn(2, 5, 64\)   \# Target sequence  
output \= transformer(src, tgt)

print(f"Full Transformer output shape: {output.shape}")

## **Use When**

> * Prototyping custom end-to-end sequence-to-sequence applications (e.g., translation, summarization, or audio-to-text).

## **Avoid When**

> * Implementing state-of-the-art causal LLMs (GPT/LLaMA) or vision-only Transformers.

## **Gotchas**

> * Default batch\_first=False can lead to subtle shape mismatch errors.  
> * Generating target sequence masks (generate\_square\_subsequent\_mask) is mandatory to prevent causal target leakage during training passes.

## **Performance Notes**

> * Large memory footprint; leverage mixed precision (torch.cuda.amp) and norm\_first=True for efficient large-scale training.
